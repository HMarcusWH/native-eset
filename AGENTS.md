# Native ESET — agent build and scientific authority rules

These instructions apply to every human/AI contributor (including Codex/Claude) working on the source tree.

**Research software is not a validated cosmological theory.** A green CI run, stable graph view, numerical agreement, or fitted score does not admit a physical provider or validate ESET.

## Mandatory orientation

1. Read `README.md`, `docs/BUILD_STATE.md`, `config/graph_snapshot.lock.json`, `registry/model_lineage.json` and the scoped task receipt.
2. Recover exact current Git commit, input hashes, last known-good archive, and relevant scientific source IDs before editing.
3. Keep legacy ESET 3/4, historical variable-F Addendum G and fixed-M_P one-map v1.7.2 in separate theory/model identities. An equation substitution is NOT a parameter change.
4. Work in a PR-sized bounded increment with acceptance tests and explicit non-change zones. Keep archival code and source data byte-identical and read-only; never refit historical comparisons during recovery.
5. Review negative outcomes as first-class historical evidence. Preserve known J2141 geometry-projection fragility, KiDS/GAMA R1 known-signal failure and missing P3/FTH5 physical source gates.

## Authority and graph firewall

- The ESET Theory-State canonical graph is immutable input to this repository. Only the governing Theory-State project can issue approved scientific decisions.
- The graph reader is a deterministic **navigation view**. Edges and semantic overlays cannot mint scientific truth.
- The source resolver's explicit subject/candidate/axis/scope/facet semantics are controlling. Do not replace it with latest-date-wins or `PASS`-means-admitted heuristics.
- Never take `provider_admitted`, `PHYSICAL_PROVIDER_ADMITTED` or `evidence_hash` directly from a caller and treat them as authority.
- Physically admitted **scoped** ESET outputs are not automatically cosmological predictions, holdout validation, unrestricted physical outputs or production-scoring permissions.
- Missing controlling authority, unselected source, stale graph SHA, unknown scope, missing microphysical provider or conflicting active verdict must fail closed.
- Keep experimental/candidate/LLM-deduced edges in separate **NON_CANONICAL_PROPOSALS** records, never in 31 sealed JSONL source partitions.

## Numeric and empirical method

- Bind units, frame, gauge, coordinate and source model IDs to every RunSpec, result and comparison.
- A change in parameters, input source, source equation hash, numerical method or code SHA creates a distinct run identity. A change in constitutive/field equations requires a new finite model/theory identity and a separate comparison.
- Always run source-exact regressions, negative controls, numerical convergence, stress/Bianchi conservation and entropy checks where they apply.
- Keep calibration, regression, diagnostics and heldout data roles segregated by source hash; never use a holdout to select model or normalization.
- Archive all outputs with complete reproducibility receipts, including actual executed environment, command, residuals and limitations.
- Control-only GR/ΛCDM output must always be labeled `EXTERNAL_REFERENCE_CONTROL_ONLY`.

## Delivery and handover

- No background jobs and no untracked work. Each turn produces a bounded deliverable, tests and a current-state update.
- Do not rewrite an earlier release ZIP or release receipt. Validate manifest and hashes and upload new revision; read back exact bytes before advancing `00_START_HERE`.
- Never add credentials, private Drive archives, raw FITS, hidden notebooks or unlicensed third-party source to the public repository.
- GitHub CI status is `NOT_RUN` until actual workflow evidence exists. Local Python tests do not imply GitHub Linux/Windows acceptance.
- The first real native ESET physics deliverable is a source-recovered historical solver, not a synthetic GR control.
