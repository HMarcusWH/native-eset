# Trust and integrity boundaries

B2 is a local research library, not a hostile-code sandbox. The Python interpreter, installed package, independently approved source lock and operating-system account are trusted. An attacker able to rewrite those trusted files, monkeypatch Python internals or replace the expected external digest is outside the protected boundary. Checks reduce accidental corruption, ordinary object/input forgery and unsupported scientific promotion; they do not make arbitrary Python safe.

## Covered by implemented checks

Malformed/duplicate JSON, nonfinite values, mutable input aliases, incorrect digests, missing or extra artifacts, inconsistent run identities, unsupported role/equation/frame combinations, unexpected graph partitions, missing references, fabricated resolver results, scope widening and declared data-use conflicts. A preflight examines staged filenames and a bounded set of high-confidence secret patterns without printing matched values.

## Not certified

Hash provenance or author identity without an independently trusted digest; model or observation truth; numerical results without actual replay; all secret formats; external process isolation; undeclared data exposure; arbitrary graph semantics; absence of all race conditions against a malicious local account. The offline importer uses a cooperative exclusive reservation, not a multi-user database transaction.

## Roles of hashes

Raw-byte graph hashes and the canonical graph digest are different checks. Source bytes are never newline-normalized. Only generated historical resolver output has an explicit UTF-8 LF normalization, with original raw hashes retained. A receipt sidecar stored with the receipt can catch damage but not a coordinated rewrite of both; keep the expected digest outside that directory or verify against the separately retained release digest.

## Scientific authority

A fresh exact-source resolver replay reports historical canonical decisions; it does not create them. The bootstrap reports only an enumerated admitted output class, not new empirical validation or permission to run an absent backend. Restricted admissions must remain usable; rejecting everything is not a correct scientific authorization policy.

## Release and privacy

The private 31-file scientific graph, proprietary physical solvers and survey catalogs stay outside the distributable ZIP. Original resolver and source-lock metadata are included with provenance. No project license has been selected for newly authored code. Sharing/repository visibility must be reviewed before publication.
